# ⑤ 分配金の再投資 — 日々決算・未収分配金・月末一括再投資

[← ④ 注文・訂正・取消](04-order-correction-cancel.md) ｜ [総合インデックス](README.md) ｜ 次 → [⑥ 目論見書の電子交付・書類送付](06-prospectus-delivery.md)

MMFの心臓部です。**この章のロジックが、帳票・税・残高表示・解約処理・システム負荷のすべてを規定します。** 他の章より先に、ここだけは設計を固めてください。

---

## 0. この章のゴール

1. 日々決算 → 未収分配金 → 月末一括再投資、という流れを正確に説明できる
2. **端数処理の設計ミスが「少額保有者の分配金がゼロになる」事故を招く**ことを理解する
3. 源泉徴収と再投資の順序、口座区分ごとの違いを設計できる
4. 月末が非営業日、償還月、口座閉鎖など、例外ケースを網羅できる

---

## 1. 全体の流れ

```
【毎営業日】
  委託会社が1万口あたりの分配金額を決定・通知
            ↓
  顧客ごとに日々の分配金を計算
      保有口数 ÷ 10,000 × 1万口あたり分配金額
            ↓
  「未収分配金」として積み上げる ★現金では払わない・口数も増えない
            ↓
      （これを月中ずっと繰り返す）

【月末最終営業日】
  当月の未収分配金を合計
            ↓
  源泉徴収（税引前 → 税額 → 税引後）
            ↓
  税引後金額で買付 ＝ 再投資
      税引後金額 ÷ 基準価額 × 10,000 ＝ 増加口数
            ↓
  保有口数が増える ／ 未収分配金はゼロにリセット
            ↓
  顧客へ通知（[② 顧客帳票](02-customer-documents.md)）
```

> 💡 **なぜ「未収分配金」という概念が要るのか**：毎日口数を増やすと、①取引件数が営業日数×口座数に爆発し、②信託財産留保額のロット管理が毎日増え、③帳票が毎日出る、という三重苦になります。**月末までは「未収」として残高の外側に置いておく**のが、実務上の解です。

## 2. 未収分配金の管理

### 2-1. データとして持つべきもの

| 項目 | 内容 | 備考 |
| --- | --- | --- |
| 顧客・口座・銘柄 | キー | 口座区分（特定／一般）も必要 |
| **未収分配金（税引前）** | 当月の累計額 | ★**小数で保持する**（[3節](#3-最重要-端数処理の設計)） |
| 日次の明細 | 日付ごとの分配金額と対象口数 | 検証・照会・訂正のために必要 |
| 直近の再投資日 | 最後にリセットされた日 | — |
| 当月の分配対象日数 | 月中買付・解約があった場合の按分に使う | — |

### 2-2. 「いつの口数」に対して分配するか

ここは仕様を明確にしないと、必ず認識がずれます。

| 論点 | 選択肢 | 影響 |
| --- | --- | --- |
| 分配対象の口数の基準日 | 前営業日末残／当日約定後残 | 当日買付分に当日の分配を付けるか |
| **当日買付した口** | 当日分から分配する／翌営業日から | 顧客の期待値と一致させる |
| **当日解約した口** | 解約日の分配を付ける／付けない | ★解約時の精算額に直結 |

> 🔍 **確認事項**：これは**信託約款の定め**によります。委託会社に「分配金の計算基準日」を確認し、そのとおりに実装してください。自社で決められる事項ではありません。

## 3. 【最重要】端数処理の設計

### 3-1. これを間違えると、少額保有者の分配金がゼロになります

具体例で示します。

```
【前提】
  顧客Aの保有額： 10,000円（10,000口）
  年率換算の分配率： 0.5%
  1日あたりの分配金 ＝ 10,000円 × 0.5% ÷ 365日 ≒ 0.137円

【やってはいけない設計】日々、円未満を切り捨てる
  4/1  0.137円 → 切捨 → 0円
  4/2  0.137円 → 切捨 → 0円
  ...
  4/30 0.137円 → 切捨 → 0円
  ───────────────────────────────
  当月の分配金合計 ＝ 0円   ★★★ 顧客は永久に分配金を受け取れない ★★★

【正しい設計】日々は小数のまま保持し、月末に合計してから円未満処理
  4/1〜4/30 の合計 ＝ 0.137円 × 30日 ≒ 4.11円
  月末に円未満処理 → 4円
  ───────────────────────────────
  当月の分配金合計 ＝ 4円   ✅ 正しく分配される
```

> ⚠️ **これは机上の話ではありません。** MMFは少額から購入でき、かつ低金利局面では1日あたりの分配金が1円を大きく下回ります。**日々の円未満切捨は、実質的に「少額顧客からの分配金の取り上げ」**になり、苦情・当局指摘のリスクがあります。

### 3-2. 端数処理を決めるべき箇所（5か所）

| # | 箇所 | 決めること | 推奨 |
| --- | --- | --- | --- |
| **1** | 日々の分配金計算 | 小数何桁まで保持するか | **小数を保持**（切り捨てない）。桁数は約款・委託会社仕様に合わせる |
| **2** | 月末の分配金合計 | 円未満をどう処理するか | 約款・委託会社の定めに従う |
| **3** | **源泉税額** | 円未満の処理 | **切捨が一般的**だが要確認 |
| **4** | 再投資口数 | 1口未満の処理 | 切捨が一般的。切捨分の扱いを決める |
| **5** | 信託財産留保額 | 円未満の処理 | 約款に従う（[④ 9節](04-order-correction-cancel.md#9-信託財産留保額とロット管理mmf固有の難所)） |

> 🔍 **確認事項（必須）**
> - **委託会社へ**：分配金の計算式、保持する小数桁数、端数処理の方法。**約款および委託会社の計算方法と完全に一致させる必要があります**
> - **税務部門へ**：源泉税額の端数処理（法令上の定め）
> - **大和総研へ**：ソナーの端数処理がどうなっているか、設定変更可能か
>
> ⚠️ **委託会社の計算とソナーの計算が1円でもずれると、毎日リコンサイル差異が出ます。** [⑨ 残高照合](09-trustee-settlement.md)で必ず検証してください。

### 3-3. 端数の累積差異

切捨を繰り返すと、顧客合計とファンド全体の分配金額にわずかな差が出ます。

| 論点 | 対応 |
| --- | --- |
| 切捨で生じた差額はどこへ行くか | 信託財産に残る／販売会社が調整する。**約款で確認** |
| 差額の会計処理 | 経理部と確認（[③](03-internal-documents.md)） |
| 差額の監視 | 日次のリコンサイル項目に含める |

## 4. 源泉徴収と再投資の順序

### 4-1. 処理順序

```
  ① 当月の未収分配金を合計          … 税引前の分配金額
            ↓
  ② 源泉徴収税額を計算              … 口座区分・顧客属性による
            ↓
  ③ 税引後金額 ＝ ① − ②
            ↓
  ④ 税引後金額で再投資              … 「税引後で買う」のがポイント
            ↓
  ⑤ 増加口数 ＝ ③ ÷ 基準価額 × 10,000（端数処理）
```

> ⚠️ **「税引前の金額で再投資して、後から税金を引く」設計にしないでください。** 顧客の口数と現金が合わなくなります。**必ず「源泉徴収 → 税引後金額で再投資」の順**です。

### 4-2. 口座区分・顧客属性による違い

| 顧客属性・口座区分 | 分配金（利子所得）の源泉徴収 | 損益通算 | 備考 |
| --- | --- | --- | --- |
| 個人・特定口座（源泉徴収あり） | あり | **口座内で自動通算** | 最も標準的 |
| 個人・特定口座（源泉徴収なし） | 要確認 | — | ★**分配金を受け入れられるのは源泉徴収選択口座のみ**という制約がある。要確認 |
| 個人・一般口座 | あり | 確定申告で対応 | — |
| **法人** | あり（**税率が個人と異なる**） | — | ★住民税相当分の扱いが個人と違う。**要確認** |
| 非居住者 | 租税条約による | — | スコープOut推奨（[①](01-overview.md)） |

> 🔍 **確認事項（必須・税務部門へ）**
> 1. 公社債投資信託の分配金（**利子所得**）について、口座区分ごとの源泉徴収の要否と税率
> 2. 特定口座（源泉徴収なし）で、分配金を口座に受け入れられるか
> 3. **法人口座**の場合の源泉徴収税率
> 4. 源泉徴収税額の端数処理
>
> ⚠️ **本ガイドに税率の具体的数値は記載していません。** 税率・区分は改正されます。設計に入れる前に、必ず税務部門または税理士の確認を取り、**その回答を要件定義書に根拠として明記**してください。詳細は[⑪ 口座・税制](11-tax-nisa-account.md)を参照。

### 4-3. 損益通算との関係

特定口座（源泉徴収あり）では、分配金と譲渡損失の損益通算が口座内で自動的に行われます。MMFの分配金も、**上場株式等の譲渡損失との通算の対象になり得ます**。

- 分配金を受け取った月に、別の商品で譲渡損失が出ていた場合の還付処理
- 年間を通じた通算と、年末の確定処理
- これらが**月末再投資のタイミングとどう噛み合うか**

> 🔍 **大和総研へ**：ソナーの特定口座管理機能において、公社債投信の分配金が損益通算の対象として正しく処理されるか。**株式投信の分配金と処理が異なる点**に注意して確認してください。

## 5. 再投資の実行

### 5-1. 再投資日の決定

| 論点 | 設計 |
| --- | --- |
| **再投資日** | 原則、月末最終**営業日** |
| **月末が土日祝の場合** | 直前の営業日に前倒し（一般的）／翌月第1営業日 → **約款で確認** |
| 年末年始 | 12月末の最終営業日。年間取引報告書の作成と重なる（[③](03-internal-documents.md)） |
| 連休をまたぐ場合 | 分配対象日数の計算に休日を含めるか |

### 5-2. 再投資時の基準価額

| 論点 | 設計 |
| --- | --- |
| どの日の基準価額を使うか | 再投資日の基準価額（一般的） |
| 基準価額が未着の場合 | ★**再投資バッチが実行できない**。翌営業日に繰り延べるか、業務判断で対応（[⑬](13-compliance-ops.md)） |
| 元本割れしている場合 | 基準価額 < 10,000円でも計算式は同じ。**ハードコードしていると破綻する** |

### 5-3. 再投資の取引記録

| 論点 | 設計 |
| --- | --- |
| 取引として記録するか | ◎ 記録する。**累積投資勘定元帳**の対象（[③ 5節](03-internal-documents.md#5-法定帳簿最重要)） |
| 取引報告書を出すか | [② 2節](02-customer-documents.md#2-最重要日々決算による帳票爆発問題)の方針に従う |
| **取得日（ロット）の扱い** | ★[④ 9節](04-order-correction-cancel.md#9-信託財産留保額とロット管理mmf固有の難所)の論点2と同一。**必ず整合させる** |
| 取得単価への反映 | 税務上の取得単価を再計算（[⑪](11-tax-nisa-account.md)） |

## 6. 例外ケース

**ここが設計の抜けどころです。** 一覧化して、すべてに答えを用意してください。

| # | ケース | 論点 | 設計の方向性 |
| --- | --- | --- | --- |
| **1** | **月中に全部解約** | 未収分配金をどう精算するか | [④ 7節](04-order-correction-cancel.md#7-全部解約と未収分配金)。解約代金に含めるのが分かりやすい |
| **2** | **月中に一部解約** | 未収分配金を按分するか据え置くか | 按分せず据置が一般的だが要確認 |
| **3** | **月中に新規買付** | 買付日からの日割り計算 | 分配計算基準日の定めに従う |
| **4** | **分配金がゼロの日** | 運用収益がマイナスの日 | 0円として処理。マイナス計上はしない |
| **5** | **当月の分配金合計が端数以下** | 税引後がゼロになる | 再投資せず未収として翌月繰越するか、0円処理か。**要判断** |
| **6** | **元本割れ（基準価額 < 10,000円）** | 再投資単価が変わる | 計算式どおり処理。[⑬](13-compliance-ops.md)の対応手順へ |
| **7** | **月末時点で口座が閉鎖済** | 再投資先がない | ★現金で支払う／閉鎖を保留する。**支払先口座の確保が必要** |
| **8** | **月末時点で取引制限中** | 再投資してよいか | コンプラと要協議 |
| **9** | **償還月** | 最終分配と償還の順序 | 償還時に未収分配金を精算して支払う |
| **10** | **顧客が死亡** | 相続手続中の分配 | 既存の相続実務に準じる。**未収分配金の扱いを明記** |
| **11** | **口座区分の変更**（一般→特定） | 月中に変更された場合の分配の帰属 | 税務部門と要確認 |
| **12** | **再投資バッチの失敗** | 一部の口座で処理が失敗 | リラン可能な設計。**部分成功を許すか、全件ロールバックか** |
| **13** | **基準価額の遡及訂正** | 再投資済みの口数が誤りになる | 再計算・訂正処理（[④ 6節](04-order-correction-cancel.md#6-受渡後の誤り事故訂正)） |

> ⚠️ **ケース7（口座閉鎖済）は実際によく起こります。** 月中に全部解約して口座を閉じた顧客に、月末の再投資が走ろうとするパターンです。**解約時に未収分配金を精算しきる設計（ケース1のA案）にしておけば、この問題は起きません。** 設計の一貫性が効く好例です。

> ⚠️ **ケース12（バッチ失敗）は非機能要件です。** 月末再投資は全保有口座を対象とする最大のバッチです。途中で失敗したときに「どこまで処理済みか」が分からないと、二重再投資や未処理が発生します。**冪等性とリラン設計を必須要件にしてください。**

## 7. 顧客への表示要件

| 表示項目 | 場所 | 論点 |
| --- | --- | --- |
| **保有口数** | 残高照会画面 | 月末に増える |
| **評価額** | 残高照会画面 | 口数 × 基準価額 ÷ 10,000 |
| **★未収分配金** | 残高照会画面 | ★**表示するかどうかが大きな分岐**。表示しないと「分配金がもらえていない」と誤解される |
| 当月の分配金（税引前／税引後） | 分配金履歴画面 | — |
| 累計の分配金 | 分配金履歴画面 | 何年分表示するか |
| 源泉徴収税額 | 分配金履歴画面 | 内訳の表示 |
| 再投資による増加口数 | 分配金履歴画面 | — |
| **分配実績（利回り）** | ファンド詳細画面 | ★**7日間平均利回り**などの実績表示。[⑧](08-info-vendor.md) |
| 元本保証でない旨 | ファンド詳細・注文画面 | ★**必須**。過去に元本割れ事例あり |

> 💡 **「未収分配金」を表示するかは、UXとシステムの両面で効く判断です。**
> - **表示する**：顧客の理解は正確になるが、「未収分配金とは何か」の説明が必要。データ項目とIFが増える
> - **表示しない**：画面はシンプルだが、月中に「分配金が付いていない」という問合せが増える
>
> **推奨は「表示する＋ツールチップで説明」**です。コールセンターの問合せ削減効果が、開発コストを上回ることが多いです。

## 8. システム負荷とバッチ設計

月末再投資は、**年間で最大のバッチ処理**です。

| 観点 | 検討事項 |
| --- | --- |
| 処理件数 | MMF保有口座数 × 1件。将来の口座数増加を見込む |
| 処理時間 | バッチウィンドウ内に収まるか。**月末＋年末が重なる12月が最長** |
| 他バッチとの順序 | 分配金確定 → 源泉徴収 → 再投資 → 残高確定 → 帳票生成 → 月末残高帳 |
| **リラン設計** | 途中失敗時に再実行できるか。処理済みをスキップできるか（冪等性） |
| 部分失敗の扱い | 一部口座のエラーで全体を止めるか、スキップして続行しエラーリストを出すか |
| 翌営業日への影響 | バッチが延伸した場合、翌朝のサービス開始に間に合うか |
| 監視・アラート | 想定時間を超過した場合の検知 |

> 🔍 **大和総研へ**：月末再投資バッチの標準的な処理時間と、口座数に対するスケーラビリティ。リラン手順。他社事例での実績値。

## 9. ソナー連携の論点

| 論点 | 確認すること |
| --- | --- |
| 分配金データの受領 | 委託会社からの1万口あたり分配金額を、**誰がどう受け取ってソナーに投入するか** |
| 日々の分配金計算 | ソナーが標準で行うか。**MRFで同等の処理をしているか** |
| 未収分配金の保持 | ソナーが未収分配金の項目を持つか。フロントへ提供するIFはあるか |
| 源泉徴収計算 | 公社債投信（利子所得）の税計算に対応しているか |
| 再投資処理 | 月末一括再投資の標準機能があるか |
| 端数処理 | 設定変更可能か。委託会社の計算と一致させられるか |
| 例外処理 | [6節](#6-例外ケース)の13ケースがどこまで標準で処理されるか |

### 大和総研への質問リスト（分配金編）

1. 日々決算型ファンドの分配金計算・月末一括再投資は、標準機能で提供されますか
2. 日々の分配金を**小数で保持**し、月末に合計してから端数処理する方式に対応していますか
3. 端数処理の方法（桁数・切捨／切上／四捨五入）は設定で変更できますか
4. **未収分配金**の残高をソナー側で保持しますか。フロントへ提供するIFはありますか
5. 公社債投信の分配金（**利子所得**）に対する源泉徴収計算に対応していますか。株式投信（配当所得）とは別の処理になっていますか
6. 特定口座（源泉徴収あり）における損益通算の対象として、正しく処理されますか
7. 法人口座の場合の源泉徴収税率の切替に対応していますか
8. [6節](#6-例外ケース)の例外ケース13件のうち、標準機能で処理されるものはどれですか
9. 月末再投資バッチの処理時間の実績値と、リラン手順を教えてください
10. 再投資により取得した口数の**取得日（ロット）の扱い**は、設定で変更できますか

## 10. テスト観点（先に読んでおくと設計が締まる）

分配金・再投資は、**日付を動かさないと検証できません**。[⑭ テスト](14-test-release.md)で詳述しますが、設計時に意識すべき点を挙げます。

| テストケース | 何を確認するか |
| --- | --- |
| 1か月まるごとの日次分配 → 月末再投資 | 累計額と再投資口数の一致 |
| **少額保有者**（1万円程度）の分配 | ★[3節](#3-最重要-端数処理の設計)の端数問題が出ないか |
| 月中買付 → 月末再投資 | 日割り計算の正確性 |
| 月中一部解約 → 月末再投資 | 未収分配金の按分 |
| **月中全部解約** | 未収分配金の精算額 |
| 月末が土日祝 | 再投資日の前倒し／後ろ倒し |
| 2か月連続 | 未収分配金のリセットが正しいか |
| 年末（12月末） | 再投資と年間取引報告書の順序 |
| 口座区分別 | 特定（源泉あり）・一般・法人での税額の違い |
| 元本割れ時 | 基準価額 ≠ 10,000円 での口数計算 |
| バッチ途中失敗 → リラン | 二重再投資が起きないか |
| 委託会社の計算との突合 | ★**1円単位で一致するか** |

## 11. この章のチェックリスト

- [ ] 日々決算 → 未収分配金 → 月末再投資 の流れが図で文書化されている
- [ ] 分配金の計算基準日（当日買付・当日解約の扱い）を**約款ベースで**委託会社に確認した
- [ ] **端数処理を5か所すべて**について決定し、委託会社の計算方法と一致させた

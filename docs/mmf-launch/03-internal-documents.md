# ③ 社内帳票 — オペレーション・経理・コンプラ・法定帳簿

[← ② 顧客帳票](02-customer-documents.md) ｜ [総合インデックス](README.md) ｜ 次 → [④ 注文・訂正・取消](04-order-correction-cancel.md)

社内帳票は、顧客帳票と違って「なくても顧客からクレームが来ない」ため、要件定義で後回しにされがちです。しかし **業務が回らなくなるのは社内帳票が足りないとき** であり、**当局検査で問題になるのも社内帳票（法定帳簿）** です。

---

## 0. この章のゴール

1. 社内帳票を5つのカテゴリで棚卸しでき、漏れを防げる
2. **法定帳簿**として作成・保存が必要なものを識別できる
3. 「帳票」ではなく「データ（CSV／BI）」で足りるものを切り分けられる
4. 締め処理のタイムラインと帳票出力の関係を設計できる

---

## 1. 社内帳票の5カテゴリ

社内帳票は、**誰が何のために見るか**で分類すると漏れません。

| カテゴリ | 誰が見るか | 目的 | 節 |
| --- | --- | --- | --- |
| **① オペレーション帳票** | 業務部・事務センター | その日の業務を回す。異常を検知する | [2節](#2-オペレーション帳票日次) |
| **② 経理・会計帳票** | 経理部 | 仕訳を起こす。収益を計上する | [3節](#3-経理会計帳票) |
| **③ コンプライアンス帳票** | コンプラ部・内部管理責任者 | 不適切な取引を検知する | [4節](#4-コンプライアンスモニタリング帳票) |
| **④ 法定帳簿** | 当局検査・内部監査 | **法令上の作成・保存義務** | [5節](#5-法定帳簿最重要) |
| **⑤ 経営管理帳票** | 経営企画・商品部 | 事業の状況を把握する | [6節](#6-経営管理kpi) |

---

## 2. オペレーション帳票（日次）

業務部が「今日の仕事」を回すための帳票です。**1日のタイムラインに沿って並べる**と漏れません。

| タイミング | 帳票 | 内容 | MMF固有の注意 |
| --- | --- | --- | --- |
| **始業前** | 営業日確認・システム稼働状況 | 当日が営業日か、バッチが正常終了したか | 月末最終営業日は再投資バッチの成否確認が必須 |
| 始業前 | **基準価額受領確認リスト** | 委託会社から基準価額が届いているか | **未着なら注文を受けられない**。[⑬](13-compliance-ops.md)の障害対応へ |
| 始業前 | 前日エラーリスト | 前日バッチのエラー・未処理分 | — |
| 日中 | **注文受付状況一覧** | 受付済み注文の件数・金額 | 締め時刻に向けた進捗管理 |
| 日中 | **エラー注文リスト** | 余力不足・口座不備などで保留中の注文 | 締め前に潰さないと翌日繰越になる |
| 日中 | 訂正・取消依頼一覧 | 承認待ちの訂正・取消 | [④](04-order-correction-cancel.md)の承認フローと連動 |
| **締め後** | **約定明細一覧** | 当日の全約定 | 委託会社への伝送内容と一致するか |
| 締め後 | **委託会社伝送結果** | 送信件数・受領確認・リジェクト | リジェクトは当日中に対処が必要 |
| 締め後 | 資金決済予定表 | 翌営業日の資金過不足 | [⑨](09-trustee-settlement.md) |
| **夜間バッチ後** | **残高照合（リコンサイル）結果** | 自社残高 vs 委託会社／ほふりの記録 | **差異があれば翌朝までに調査** |
| 夜間バッチ後 | 帳票出力結果一覧 | 顧客帳票の出力件数・エラー | [②](02-customer-documents.md) |

### 月次・特定日のオペレーション帳票

| タイミング | 帳票 | MMF固有の注意 |
| --- | --- | --- |
| **月末最終営業日** | **分配金再投資処理結果** | ★最重要。対象口座数・分配金総額・再投資口数・源泉税額の合計 |
| 月末最終営業日 | 再投資エラーリスト | 再投資に失敗した口座（口座閉鎖中など） |
| 月次 | 未収分配金残高一覧 | 月中の未収分配金の総額 |
| 年末 | 年間取引報告書 作成対象リスト | [⑪](11-tax-nisa-account.md) |
| 償還時 | 償還処理対象・結果一覧 | 未収分配金の最終精算を含む |

> 💡 **設計のコツ**：オペレーション帳票は **「紙の帳票」である必要はほぼありません**。画面照会とCSVダウンロードで足りることが大半です。要件定義で「帳票」と書くと印刷前提の開発になるため、**「画面／CSV／帳票」のどれかを明記**してください。コストが変わります。

## 3. 経理・会計帳票

MMFで自社に入る収益は、主に **代行手数料**（信託報酬のうち販売会社の取り分）です。

### 3-1. 収益の流れ

```
 信託財産から日々、信託報酬が控除される
            │
            ├─→ 委託会社の取り分（運用の対価）
            ├─→ 受託会社の取り分（保管・管理の対価）
            └─→ 【販売会社（自社）の取り分＝代行手数料】
                        │
                        │ 通常は月次または決算期ごとに
                        │ 委託会社から自社へ支払われる
                        ▼
                  自社の収益として計上
```

### 3-2. 必要な帳票・データ

| 帳票 | 内容 | 論点 |
| --- | --- | --- |
| **代行手数料 計算明細** | 日々の平均残高 × 料率 で算出した根拠 | **自社計算と委託会社計算の一致確認**が必要 |
| 代行手数料 請求・入金消込 | 請求額と入金額の突合 | 差異時の調査フロー |
| **仕訳データ** | 会計システムへ連携する仕訳 | 勘定科目、計上タイミング、消費税区分 |
| 預り資産残高表 | MMFの預り残高（銘柄別・部店別） | 経営管理KPIと共通化できる |
| 未収収益計上 | 期末時点の未収代行手数料 | 決算期をまたぐ場合 |
| 源泉税預り金 | 分配金から源泉徴収した税額の預り・納付 | **月末再投資で大量に発生**。納付期限に注意 |

> 🔍 **確認事項（3点）**
> 1. **経理部へ**：代行手数料の収益計上基準（発生基準／入金基準）と勘定科目。消費税の取扱い
> 2. **委託会社へ**：代行手数料の料率、計算方法（日々平均残高か月末残高か）、支払サイクル、明細の提供形式（[⑦](07-management-company.md)）
> 3. **大和総研へ**：ソナーが代行手数料の計算機能を持つか。会計システムへの仕訳連携IFは標準であるか

> ⚠️ **落とし穴**：源泉徴収した税額の**納付期限**は法令で定まっています。月末再投資で発生した源泉税を、期限内に納付する業務フローとチェック帳票を必ず設計してください。ここは[⑪](11-tax-nisa-account.md)と併せて税務部門の確認が必須です。

## 4. コンプライアンス・モニタリング帳票

### 4-1. 必要なモニタリング

| モニタリング | 帳票・アラート | MMFでの位置づけ |
| --- | --- | --- |
| **適合性原則** | 適合性チェック結果、不適合取引リスト | MMFは低リスク商品だが、**確認手続は必要** |
| **高齢顧客取引** | 高齢者取引一覧、承認記録 | 社内の高齢者ルールの適用対象か要判断 |
| **大口取引** | 一定金額以上の買付・解約 | 資金繰りへの影響把握も兼ねる |
| **短期売買・回転売買** | 短期間での買付解約の繰返し | **MMFは信託財産留保額があるため、短期解約は顧客不利益**。モニタリング対象にする価値が高い |
| **AML/CFT** | 疑わしい取引の検知、閾値超過 | 犯収法。**MMFは換金性が高く、資金の出入りに使われるリスクがある** |
| **反社チェック** | 新規口座・取引時のスクリーニング結果 | 既存の仕組みに相乗り |
| **苦情・トラブル** | 苦情記録簿、対応状況 | 新商品は初期に苦情が出やすい |
| **勧誘記録** | 勧誘の記録（対面・電話がある場合） | Web完結ならスコープ外にできる |

> 💡 **MMF特有の注目点**：MMFは **「元本が安定していると誤解されやすい」** 商品です。過去に元本割れの事例があり、販売時の説明が不十分だと苦情に直結します。
> - サイト上の表示に「元本保証ではない」旨が適切に記載されているか（[⑫](12-web-nonfunctional.md)）
> - 苦情の傾向を早期に把握できるモニタリング帳票を、**リリース直後の集中監視期間**で用意する（[⑭](14-test-release.md)）

### 4-2. AML/CFTの具体的な論点

MMFは即日に近いサイクルで換金できるため、資金移動の経路として使われるリスクがあります。

- 入金 → MMF買付 → 短期間で解約 → 出金、という一連の動きの検知
- 出金先口座の変更と、その直後の大口解約の組合せ
- 閾値の設定（金額・頻度）と、既存のAMLシステムへの銘柄追加

> 🔍 **確認事項**：自社のAML/CFTモニタリングシステムに、**新銘柄を追加する作業が必要か**。閾値やシナリオの見直しが必要か。AML担当部署に早期に照会してください。この作業は見落とされやすく、直前に発覚すると審査に時間がかかります。

## 5. 法定帳簿（最重要）

金融商品取引業者には、**法令に基づく帳簿書類の作成・保存義務**があります。ここは「作らない」という選択肢がありません。

### 5-1. MMFで関係する主な帳簿書類

| 帳簿書類 | 内容 | MMFでの注意 |
| --- | --- | --- |
| **注文伝票** | 注文の受付記録（顧客・銘柄・数量・時刻など） | **訂正・取消の記録も含む**（[④](04-order-correction-cancel.md)） |
| **顧客勘定元帳** | 顧客ごとの取引・預り金・預り有価証券の記録 | — |
| **累積投資勘定元帳** | **累積投資契約に基づく取引の記録** | ★**分配金再投資は累積投資契約に基づくため、この帳簿が必要になる** |
| **顧客有価証券勘定元帳** | 顧客から預かった有価証券の記録 | 投資信託受益権 |
| **月末残高帳** | 月末時点の残高記録 | 月末再投資後の残高で作成 |
| **取引残高報告書の写し** | 顧客に交付した報告書の控 | [②](02-customer-documents.md)と連動 |
| 取次ぎ等に係る記録 | 媒介・取次ぎ・代理の記録 | 販売形態による |

> ⚠️ **「累積投資勘定元帳」を見落とさないでください。** 分配金の再投資は累積投資契約に基づく取引として扱われるのが一般的で、専用の法定帳簿が必要になります。株式投信の再投資型ファンドを既に扱っていれば既存の仕組みに乗る可能性が高いですが、**扱っていない場合は新規対応**になります。

> 🔍 **確認事項（2点）**
> 1. **コンプライアンス／法務へ**：本件で作成・保存が必要な法定帳簿の一覧と、**それぞれの保存年限**。帳簿書類ごとに年限が異なります（5年・7年・10年など）。必ず一覧化してください
> 2. **大和総研へ**：上記の法定帳簿がソナーの標準機能で作成・保存されるか。**累積投資勘定元帳**が標準で出るか。電子保存の要件（検索性・改ざん防止）を満たしているか

### 5-2. 保存に関する設計観点

| 観点 | 決めること |
| --- | --- |
| 保存媒体 | 電子保存か紙か。電子保存の場合の法令要件充足 |
| **保存年限** | 帳簿ごとに設定。**顧客帳票のデータ保存年限と揃える**（[②](02-customer-documents.md)） |
| 検索性 | 顧客・日付・銘柄での検索が可能か。検査時に即座に出せるか |
| 改ざん防止 | タイムスタンプ、アクセスログ、権限管理 |
| 廃棄 | 年限経過後の廃棄手続と記録 |
| 移行 | システム更改時の帳簿の引継ぎ |

## 6. 経営管理・KPI

商品を出した後、**「売れているのか」を判断する材料**です。要件定義の段階で決めておかないと、リリース後に「数字が出せない」となります。

| KPI | 定義 | 出力先 |
| --- | --- | --- |
| **預り残高（AUM）** | MMFの残高合計。日次・月末 | BI／ダッシュボード |
| **純流入額** | 買付額 − 解約額。日次・月次 | BI |
| 保有口座数 | MMFを保有する口座数 | BI |
| 新規購入口座数 | 当月初めて購入した口座数 | BI |
| 平均保有残高 | 残高 ÷ 保有口座数 | BI |
| **平均保有期間** | 解約までの平均日数 | BI。**短期解約が多いと信託財産留保額の苦情につながる** |
| 短期解約率 | 信託財産留保額が発生した解約の割合 | BI・コンプラ共有 |
| 代行手数料収益 | 月次・累計 | 経理と共通 |
| チャネル別внутренний構成 | Web／その他の比率 | BI |
| 電子交付同意率 | 郵送コストの予測に使う | 運用 |

> 💡 **BIかExcelか**：新商品のKPIは、初期は **CSV出力＋Excel** で十分です。BIツールへの組込みは残高が積み上がってから判断してもコストがかかりません。要件定義では「データ抽出のIFを用意する」ところまでを必須にし、可視化は第2フェーズに回すのが現実的です。

## 7. 当局・自主規制機関への報告

| 報告先 | 報告内容 | 頻度 | 論点 |
| --- | --- | --- | --- |
| **投資信託協会** | 販売会社としての残高・販売額等の統計報告 | 月次等 | **新銘柄の報告対象への追加作業が必要**。様式・提出方法を確認 |
| **日本証券業協会** | 各種報告 | 規則による | 既存の報告に銘柄を追加 |
| **金融庁** | 事業報告書・業務報告書等 | 年次等 | 既存の集計に含める |
| 委託会社 | 販売会社別の残高報告（代行手数料計算の根拠） | 月次等 | [⑦](07-management-company.md) |

> 🔍 **確認事項**：投資信託協会への報告について、**新規銘柄の登録手続と報告開始タイミング**を確認してください。設定日の直後から報告義務が発生する場合、リリース時点で報告用のデータ抽出ができている必要があります。

## 8. 締め処理と帳票出力のタイムライン

社内帳票は**締め処理のどのタイミングで出るか**が重要です。これを図にして合意してください。

```
 【通常日】
  15:00  Web受付締め
    │
  15:30  ソナー 注文確定バッチ ──→ [約定明細一覧]
    │                              [エラー注文リスト]
  16:00  委託会社へ伝送      ──→ [伝送結果]
    │
  18:00  基準価額受領・約定確定
    │
  20:00  夜間バッチ開始
    ├─→ 残高更新          ──→ [残高一覧]
    ├─→ 分配金日次計上    ──→ [未収分配金残高]
    ├─→ 残高照合          ──→ [リコンサイル結果]  ★差異は翌朝までに調査
    ├─→ 顧客帳票データ生成 ──→ [帳票出力結果]
    └─→ 経理仕訳データ生成 ──→ [仕訳データ]
  翌 8:00  始業前チェック    ──→ [前日エラーリスト]
                                [基準価額受領確認]

 【月末最終営業日】※上記に加えて
  20:00  夜間バッチ
    ├─→ 分配金確定・源泉徴収 ──→ [源泉税集計]      ★納付手続へ
    ├─→ 再投資口数計算       ──→ [再投資処理結果]  ★最重要
    ├─→ 再投資エラー抽出     ──→ [再投資エラーリスト]
    └─→ 月末残高確定         ──→ [月末残高帳（法定帳簿）]
```

> ⚠️ **月末と年末が重なる12月**、および**月末が連休明け**のケースで、バッチの所要時間が通常日を大きく超えます。[⑫ 非機能要件](12-web-nonfunctional.md)でバッチウィンドウを検証してください。

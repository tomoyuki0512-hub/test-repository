# ⑧ 情報ベンダーへのデータ連携（QUICK等） — 基準価額・利回り表示・コード登録

[← ⑦ 委託会社との調整](07-management-company.md) ｜ [総合インデックス](README.md) ｜ 次 → [⑨ 受託会社・決済インフラ連携](09-trustee-settlement.md)

情報ベンダー連携は「サイトに基準価額を出すだけ」に見えますが、**約定計算に使う基準価額と、サイト表示用の基準価額が別経路で来る**という構造的な落とし穴があります。ここを整理しないと、「サイトの表示と取引報告書の金額が違う」という事故になります。

---

## 0. この章のゴール

1. 情報ベンダーから来るデータと、委託会社から来るデータの**役割の違い**を説明できる
2. **MMF特有の「平均利回り」表示**の論点を理解する
3. 新ファンドのコード登録・配信開始の手続を漏れなく実施できる
4. データ遅延・欠損時のフォールバック設計ができる

---

## 1. 情報ベンダーとは

投資信託の基準価額・分配金・属性情報などを収集・加工して配信する事業者です。

| 主な事業者 | 性格 |
| --- | --- |
| **QUICK** | 総合金融情報ベンダー。国内金融機関での利用が広い |
| 時事通信社 | 報道・情報配信 |
| ウエルスアドバイザー | 投信評価・レーティング |
| 日本経済新聞社 | 報道・紙面掲載 |
| Bloomberg／LSEG | グローバルな金融情報 |
| **投資信託協会** | 自主規制機関。統計・公表データ |
| 投信評価会社各社 | レーティング、パフォーマンス分析 |

> 🔍 **確認事項**：自社が現在どの情報ベンダーと契約しているか、既存の投信情報をどこから取得しているかを、**まず社内で調査**してください。新規契約が必要か、既存契約への銘柄追加で済むかで、作業量とリードタイムが大きく変わります。

## 2. 【最重要】データの流れと「正」の所在

### 2-1. 2つの経路

```
                    ┌──────────────┐
                    │   委託会社    │ 基準価額を算出
                    └──────┬───────┘
                           │
        ┌──────────────────┴──────────────────┐
        │                                      │
   【経路A：取引用】                      【経路B：表示用】
   直接またはほふり経由                   投資信託協会／情報ベンダー経由
        │                                      │
        ▼                                      ▼
  ┌──────────┐                        ┌──────────────┐
  │  ソナー   │ 約定計算に使う          │ 自社サイト     │ 顧客への表示に使う
  └──────────┘ ★これが「正」          └──────────────┘
        │                                      │
        └────── この2つがズレると事故 ─────────┘
```

### 2-2. なぜズレるのか

| ズレの原因 | 内容 |
| --- | --- |
| **配信タイミングの差** | 委託会社からソナーへは夕方、ベンダーからサイトへは翌朝、など |
| **訂正の反映差** | 基準価額が訂正されたとき、片方だけ更新される |
| **小数桁数・丸めの差** | ベンダー側で丸めている場合がある |
| 配信停止・障害 | 片方だけ止まる |

### 2-3. 設計の原則

> ⚠️ **原則：約定・残高・帳票に使う基準価額の「正」は、委託会社から取引用経路で受領したもの（＝ソナーが保持するもの）です。**
> 情報ベンダーから受け取るデータは、**チャートや参考情報の表示用**と位置づけてください。

| 用途 | データの出所 | 理由 |
| --- | --- | --- |
| 約定計算 | **委託会社（取引用経路）** | 法的・契約的にこれが正 |
| 保有残高の評価額表示 | **ソナーが保持する基準価額** | 取引報告書と一致させる必要がある |
| ファンド詳細画面の基準価額 | 要判断 | ★**ソナー側に合わせるのが安全** |
| 基準価額チャート（履歴） | 情報ベンダー | 履歴データの保持が容易 |
| 純資産総額 | 情報ベンダー or 委託会社 | — |
| リスク指標・レーティング | 情報ベンダー | 加工データはベンダーの強み |

> 💡 **推奨**：「顧客の資産に関わる数値（評価額・約定金額）はソナー由来」「ファンドの一般情報（チャート・純資産・カテゴリ平均）はベンダー由来」と、**明確に役割を分けて設計**してください。混在させると、不一致の原因調査が極めて困難になります。

## 3. 受信するデータ

| データ項目 | 主な用途 | 出所 | 更新頻度 |
| --- | --- | --- | --- |
| **基準価額（1万口あたり）** | 表示・チャート | ベンダー／委託会社 | 日次 |
| **分配金額** | 分配実績の表示 | ベンダー／委託会社 | 日次 |
| **★平均利回り（7日間等）** | ★MMFの主要指標 | [4節](#4-mmf特有平均利回りの表示) | 日次 |
| 純資産総額 | ファンド規模の表示 | ベンダー | 日次 |
| 設定口数・解約口数 | 参考情報 | ベンダー | 日次 |
| ファンド属性（分類・投資対象） | 検索・絞込み | ベンダー／協会 | 随時 |
| 信託報酬・信託財産留保額 | 費用の表示 | ベンダー／委託会社 | 随時 |
| 騰落率・リスク指標 | 実績表示 | ベンダー | 日次／月次 |
| レーティング | 評価の表示 | 評価会社 | 月次 |
| 月次レポートPDF | 資料の掲載 | 委託会社 | 月次 |

> 💡 **MMFでは「騰落率」や「シャープレシオ」はあまり意味を持ちません。** 基準価額が10,000円付近で安定するよう運用されるためです。**表示する指標を株式投信と同じにすると、意味のない数値が並びます。** MMF用の表示項目セットを別途定義してください（[⑫](12-web-nonfunctional.md)）。

## 4. 【MMF特有】平均利回りの表示

### 4-1. なぜ必要か

MMFは基準価額がほぼ動かないため、**「騰落率」では運用成果が分かりません**。代わりに、直近の分配実績を年率換算した **平均利回り** が、顧客が比較する主要な指標になります。

```
 株式投信 → 基準価額の変化 ＝ 騰落率 で成果を表す
 MMF     → 基準価額はほぼ一定、成果は「分配金」に出る
           → 直近の分配実績を年率換算した「平均利回り」で表す
```

一般に **7日間平均利回り**（直近7日間の分配実績を年率換算したもの）が用いられ、15日間・30日間の表示が併用されることもあります。

### 4-2. 決めるべきこと

| # | 論点 | 注意 |
| --- | --- | --- |
| **1** | **どの利回りを表示するか** | 7日間／15日間／30日間。**顧客が他社と比較するため、業界の慣行に合わせる** |
| **2** | **★算出方法の出所** | 自社で計算するか、委託会社・ベンダーから提供を受けるか |
| **3** | **表示の単位・桁数** | 小数第何位まで。切捨／四捨五入 |
| **4** | 表示の更新タイミング | 日次のどの時点で更新するか |
| **5** | 設定直後の扱い | ★**設定から7日経っていない期間はどう表示するか**（「—」表示など） |
| **6** | 併記すべき注記 | 「過去の実績であり将来を保証するものではない」等 |

> ⚠️ **論点2が最重要です。** 平均利回りの算出方法は、**投資信託協会の規則等で定められている**と理解されます。**自社で独自に計算式を作らないでください。**
>
> 🔍 **確認事項（必須）**
> - **投資信託協会の規則**において、MMFの利回り表示の算出方法・表示方法がどう定められているか（コンプライアンスに確認）
> - **委託会社**が算出値を提供してくれるか。提供される場合、その値をそのまま表示すればよいか
> - **情報ベンダー**から配信されるか。配信される場合の算出方法は規則に準拠しているか
>
> **推奨は「委託会社またはベンダーから提供された値をそのまま表示する」**です。自社計算は、規則との不一致リスクと、他社との表示値の食い違いリスクを生みます。

### 4-3. 論点5（設定直後）を軽視しない

新規設定ファンドは、**販売開始直後に7日分の実績がありません**。

| 期間 | 表示 |
| --- | --- |
| 設定日〜7日未満 | 「—」または「算出期間に満たないため表示しません」 |
| 7日以降 | 7日間平均利回りを表示 |

この分岐を実装し忘れると、**販売開始日にサイトが「利回り 0.00%」と表示**します。これは誤認を招き、苦情・当局指摘のリスクがあります。**リリース直後こそ最も注目される期間**なので、必ず設計してください。

## 5. 送信するデータ

販売会社から外部へ送るデータもあります。

| データ | 送信先 | 頻度 | 目的 |
| --- | --- | --- | --- |
| **取扱ファンド情報** | 情報ベンダー | 随時 | 「どの証券会社で買えるか」の表示 |
| 販売会社別の残高・販売額 | 投資信託協会／委託会社 | 月次等 | 統計・代行手数料計算（[③](03-internal-documents.md)） |
| 取扱開始・終了の連絡 | ベンダー | 随時 | — |

> 🔍 **確認事項**：情報ベンダーの「取扱金融機関」情報に自社を掲載する手続と、その申請リードタイム。**顧客が比較サイトから流入する導線**になるため、企画部門の関心事項でもあります。

## 6. 新ファンドの登録手続

新しいファンドをサイトに表示するまでに必要な作業の一覧です。**リードタイムが読みにくい領域**なので、早期に着手してください。

| # | 作業 | 実施者 | リードタイム | 依存 |
| --- | --- | --- | --- | --- |
| 1 | **協会コード（ファンドコード）の確定** | 委託会社 | — | [⑦ #2](07-management-company.md) |
| 2 | ISINコードの確定 | 委託会社 | — | [⑦ #3](07-management-company.md) |
| 3 | 商品分類・属性区分の確定 | 委託会社 | — | [⑦ #4](07-management-company.md) |
| 4 | **ベンダーへの配信対象追加申請** | 自社 | ★要確認 | 1〜3 |
| 5 | 自社側の銘柄マスタ登録（表示用） | 自社 | — | 1〜3 |
| 6 | ソナーの銘柄マスタ登録 | 大和総研／自社 | ★要確認 | 1〜3、[⑩](10-sonar-integration.md) |
| 7 | **データ項目のマッピング確認** | 自社 | — | 4 |
| 8 | **配信テスト**（設定日前） | 自社＋ベンダー | — | 4〜7 |
| 9 | サイト表示の確認 | 自社 | — | 8 |
| 10 | 取扱金融機関情報の掲載申請 | 自社 | ★要確認 | 1 |

> ⚠️ **作業4と8がボトルネックになりやすいです。** ベンダー側の申請〜配信開始には所定の期間が必要で、かつ**新規設定ファンドはベンダー側にもデータが存在しない**ため、設定日前のテストが難しくなります。
>
> **対策**：ベンダーに「設定前のファンドのテストデータを提供してもらえるか」を早期に確認してください。提供されない場合、**設定日〜販売開始日の間に検証する期間を工程に確保**する必要があります。

## 7. データ品質・遅延・欠損時の対応

サイト表示は「データが来ている前提」で作られがちですが、**来ないことがあります**。

### 7-1. 異常パターンと対応

| # | 事象 | 影響 | 対応の設計 |
| --- | --- | --- | --- |
| 1 | **基準価額の配信遅延** | 古い値が表示され続ける | ★**データの日付を表示する**。一定時間超過で「更新中」表示に切替 |
| 2 | **基準価額の欠損** | 表示が空になる | 前日値を表示するか、「—」にするか。**前日値を無表示で出すのは誤認リスク** |
| 3 | **異常値の配信** | 桁違いの値が表示される | ★**異常値チェック**（前日比で一定率を超えたらアラート＋表示保留） |
| 4 | **分配金額の欠損** | 利回りが計算できない | 「—」表示 |
| 5 | **ベンダー側の障害** | 全データが止まる | 縮退表示（[⑫](12-web-nonfunctional.md)） |
| 6 | **基準価額の訂正** | 誤った値が表示済み | 訂正データの取込と、表示の修正。[④](04-order-correction-cancel.md)と連動 |

> ⚠️ **対応1（データの日付表示）は、最小のコストで最大の効果がある設計です。** 「基準価額 10,001円（2026年9月15日現在）」と日付を併記するだけで、遅延時の誤認を大幅に防げます。**必須要件に入れてください。**

> ⚠️ **対応3（異常値チェック）を必ず入れてください。** MMFの基準価額は10,000円付近で安定するため、**前日比で大きく動いたら、まず配信エラーを疑うべき**です。逆に言えば、異常値チェックの閾値を設定しやすい商品でもあります。ただし**本当に元本割れした場合を「異常値」として弾いてしまわないよう**、アラート＋人的確認のフローにしてください。

### 7-2. 監視

| 監視項目 | 閾値の例 | 通知先 |
| --- | --- | --- |
| 基準価額の受信 | 所定時刻までに未着 | 業務部・システム |
| 基準価額の値 | 前日比で一定率超の変動 | 業務部・システム |
| 分配金額の受信 | 所定時刻までに未着 | 業務部 |
| データの鮮度 | 最終更新から一定時間経過 | システム |
| ベンダー接続 | 接続断・認証エラー | システム |

## 8. 契約・課金・権利

見落とされやすい、しかし後で問題になる領域です。

| 論点 | 内容 |
| --- | --- |
| **契約の有無** | 新規契約が必要か、既存契約に含まれるか |
| **課金体系** | 銘柄数課金／データ項目課金／定額。**銘柄追加で費用が増えるか** |
| **★再配信の権利** | ベンダーから受けたデータを**自社サイトで一般公開してよいか**。契約上の制約を確認 |
| 利用範囲 | 社内利用のみか、顧客への提供が可能か |
| **帰属表示** | 「出所：◯◯」の表示義務があるか |
| データの二次加工 | 加工して表示してよいか |
| 保存・履歴利用 | 過去データを蓄積して自社で保持してよいか |
| 解約時 | 契約終了時のデータの取扱い |

> ⚠️ **「再配信の権利」を必ず確認してください。** 社内分析用のライセンスで契約しているデータを、顧客向けサイトに掲載すると契約違反になります。既存契約を流用する場合こそ、**契約書の利用範囲条項を読み直してください。**

## 10. 表示に関する法令・自主規制

サイトに実績値を表示する行為は、**広告等の表示**に該当し得ます。

| 論点 | 内容 |
| --- | --- |
| 広告等の表示に関する規制 | 金商法・協会規則。誇大表示の禁止 |
| **リスクの表示** | 元本割れの可能性、手数料等の明示 |
| **実績表示のルール** | 過去の実績である旨、将来を保証しない旨の注記 |
| 比較表示 | 他社商品・他ファンドとの比較の可否 |
| **文字サイズ・位置** | リスク表示を本文と同程度の大きさで表示する等の要件 |
| 表示の審査 | 自社コンプライアンスの広告審査（[⑬](13-compliance-ops.md)） |

> ⚠️ **平均利回りを大きく表示し、リスク注記を小さく表示する**のは、典型的な指摘事項です。デザイン段階からコンプライアンスを巻き込んでください（[⑫](12-web-nonfunctional.md)）。

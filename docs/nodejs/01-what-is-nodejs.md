# ① Node.jsとは何か — ブラウザの外でJSを動かす

[← 総合インデックスに戻る](README.md) ｜ 次 → [② イベントループと非同期](02-event-loop.md)

この章では **「Node.jsとは結局なんなのか」** をはっきりさせます。ここが曖昧なままだと、以降の話がすべてぼやけます。

---

## 1. Node.js は「言語」ではなく「実行環境」

まずここを間違えないでください。

```
❌ 「Node.jsという言語」          → 存在しません
❌ 「ReactとNode.jsどっちを使う？」→ 比較対象ではありません
✅ 「JavaScriptをサーバーで動かす実行環境」
```

### JavaScriptが動く場所は2つある

```
JavaScript（言語）
    ├── ブラウザ で動く   … Chrome / Safari / Firefox
    └── Node.js で動く    … サーバー・PC・CI環境
```

**同じJavaScriptという言語**を、違う場所で動かしているだけです。文法（`const`・`if`・`function`）はまったく同じです。

---

## 2. 何が違うのか — ブラウザ vs Node.js

違うのは **「使える道具（API）」** です。

| できること | ブラウザ | Node.js | 理由 |
| --- | --- | --- | --- |
| `const` `if` `class` 等の文法 | ✅ | ✅ | 同じJavaScript |
| `document.getElementById` | ✅ | ❌ | サーバーに画面はない |
| `window` / `localStorage` | ✅ | ❌ | 同上 |
| `alert()` | ✅ | ❌ | 同上 |
| `fetch()` | ✅ | ✅ | Node 18から標準搭載 |
| **ファイルの読み書き** | ❌ | ✅ | ブラウザは安全のため禁止 |
| **サーバーの起動** | ❌ | ✅ | — |
| **DBへの接続** | ❌ | ✅ | — |
| **環境変数（`process.env`）** | ❌ | ✅ | — |
| **OSの情報取得** | ❌ | ✅ | — |

> 🔑 **`window is not defined` エラーの正体**：サーバー側で `window` を使おうとしています。Next.jsでこのエラーが出るのは、Server Component や SSR 中に `window` を触っているためです（→ [Next.js④](../nextjs/04-server-client-components.md)）。

### 対応表

| ブラウザ | Node.js |
| --- | --- |
| `window` / `globalThis` | `global` / `globalThis` |
| `localStorage` | ファイル or DB |
| `location.href` | `process.argv` / `process.env` |
| `console.log` | `console.log`（同じ） |
| `alert()` | `console.log()` |

## 3. Node.jsの中身

Node.js は主に3つの部品でできています。

```
┌─────────────────────────────────────┐
│           Node.js                    │
│  ┌───────────┐  ┌────────────────┐  │
│  │ V8エンジン │  │  libuv         │  │
│  │ JSを実行   │  │  非同期I/O     │  │
│  │（Chromeと │  │  イベントループ │  │
│  │  同じもの）│  │                │  │
│  └───────────┘  └────────────────┘  │
│  ┌────────────────────────────────┐ │
│  │ 標準ライブラリ                  │ │
│  │ fs / http / path / stream ...   │ │
│  └────────────────────────────────┘ │
└─────────────────────────────────────┘
```

| 部品 | 役割 |
| --- | --- |
| **V8** | JavaScriptを機械語に変換して実行する。Chromeと同じエンジン |
| **libuv** | ファイル読み込みやネットワーク通信の「待ち」を担当。**イベントループの実体** |
| **標準ライブラリ** | `fs`（ファイル）・`http`（サーバー）などの機能 |

**V8だけではファイルも読めません。** libuvと標準ライブラリを足したものがNode.jsです。

## 4. なぜ生まれたのか — 解決した問題

### 2009年当時の課題：C10K問題

「1台のサーバーで1万台の同時接続を捌けない」という問題がありました。

```
❌ 従来（1リクエスト = 1スレッド）
   リクエストが来る → スレッドを作る → DBの応答を待つ（何もせず待機）
   スレッドはメモリを食う → 同時接続が増えると破綻

✅ Node.js（シングルスレッド + 非同期）
   リクエストが来る → DBに問い合わせを投げる → すぐ次のリクエストを受ける
   DBから返ってきたら続きを処理する
   → 待ち時間に他の仕事ができるので、少ないリソースで大量に捌ける
```

**「待っている間に他のことをする」** ——これがNode.jsの設計思想です。詳細は [② イベントループ](02-event-loop.md)。

### 副産物として得られた大きな利点

| 利点 | 内容 |
| --- | --- |
| **言語の統一** | フロントもバックもJavaScript。学習コストが半分に |
| **コードの共有** | 型定義・バリデーション・ユーティリティを共用できる |
| **npm** | 世界最大級のパッケージ資産 |
| **SSRの実現** | サーバーでReactを実行できる → **Next.jsが成立する前提** |

> 🔑 **Next.jsとの関係**：サーバーでJavaScriptが動くから、サーバーでReactを実行してHTMLを作れる。**Node.jsがなければNext.jsは存在しません**（→ [関係ガイド](../js-stack-relations.md)）。

## 5. Node.jsの得意・不得意

**万能ではありません。** ここを知っておくと技術選定を誤りません。

### ✅ 得意：I/O待ちが多い処理

```
・Webサーバー / REST API
・リアルタイム通信（チャット・通知）
・BFF（フロント専用のAPI集約層）
・DBやAPIを呼んで結果を返す処理
・CLIツール・ビルドツール
```

### ❌ 不得意：CPUを長時間使う処理

```
・画像/動画のエンコード
・機械学習の学習処理
・巨大データの集計・暗号計算
```

**理由**：シングルスレッドなので、重い計算をしている間は**他のリクエストが一切処理されません**。

```
リクエストA: 5秒かかる画像処理を実行
リクエストB: ← 5秒間まったく応答が返らない
リクエストC: ← 同上
```

> 💡 **どうしても必要な場合**：`worker_threads` で別スレッドに逃がす、専用のジョブキュー（BullMQ等）に投げる、その部分だけGoやPython/Rustで書く、といった対処をします。

## 6. インストールと最初の一歩

### バージョン管理ツールを使う

プロジェクトごとにNode.jsのバージョンが違うことは普通にあるため、**バージョン管理ツールの利用を推奨**します。

| ツール | 特徴 |
| --- | --- |
| **fnm** | Rust製で高速。おすすめ |
| **nvm** | 定番。情報が多い |
| **Volta** | プロジェクトごとに自動切替 |
| 公式インストーラ | 手軽だが切り替えができない |

```bash
# fnm の例
fnm install 24
fnm use 24
node -v      # v24.x.x
```

`.nvmrc` や `package.json` の `engines` にバージョンを書いておくと、チームで揃えられます。

```json
// package.json
{
  "engines": { "node": ">=24.0.0" }
}
```

### 最初のプログラム

```js
// hello.js
console.log('Hello, Node.js!')
console.log('Node version:', process.version)
console.log('現在のディレクトリ:', process.cwd())
```

```bash
node hello.js
```

### 対話モード（REPL）

```bash
node
> 1 + 1
2
> process.platform
'linux'
> .exit
```

ちょっとした動作確認に便利です。

### TypeScriptを直接実行する

**Node.js 24 では、TypeScriptファイルをそのまま実行できます**（型注釈を取り除いて実行する方式）。

```bash
node script.ts     # ビルド不要
```

> ⚠️ ただしこれは「型を無視して実行する」だけで、**型チェックはしません**。型エラーの検出には別途 `tsc --noEmit` が必要です。本番のビルドには従来どおり `tsc` や `tsx`・`esbuild` を使うのが確実です。

## 7. Deno と Bun — 後発の選択肢

| | **Node.js** | **Deno** | **Bun** |
| --- | --- | --- | --- |
| 登場 | 2009 | 2020 | 2022 |
| 作者 | — | Node.jsの原作者 | — |
| TypeScript | 24から直接実行可 | 標準対応 | 標準対応 |
| セキュリティ | 制限なし | **既定で権限制限** | 制限なし |
| 速度 | 標準 | 速い | **非常に速い** |
| npmパッケージ | ネイティブ | 互換対応 | 互換対応 |
| **エコシステム** | **圧倒的** | 発展途上 | 発展途上 |
| **実務での採用** | **標準** | 限定的 | 増加中 |

### どれを学ぶべきか

```
✅ まず Node.js を学ぶ

理由：
  ・求人・情報・ライブラリの量が圧倒的
  ・Next.js・Vercel など主要なエコシステムがNode.js前提
  ・知識の大半はDeno/Bunにそのまま応用できる
  ・企業の既存システムはほぼNode.js
```

Bun は「パッケージインストールが速い」「テストランナーが内蔵」といった開発体験の良さで採用が増えていますが、**本番運用の実績とライブラリ互換性ではNode.jsが依然として標準**です。

---

## 8. この章のまとめ

- **Node.jsは言語ではなく「実行環境」**。ReactやNext.jsと比較する対象ではない
- ブラウザとの違いは**使えるAPI**。`window`/`document` はなく、代わりにファイル・ネットワーク・DBが使える
- 中身は **V8（JS実行）＋ libuv（非同期I/O）＋ 標準ライブラリ**
- 設計思想は **「待っている間に他のことをする」**（シングルスレッド＋非同期）
- ✅ **I/O待ちが多い処理が得意**、❌ **CPUを長時間使う処理は苦手**
- 本番では **偶数バージョンのLTS（24系）** を使う。バージョン管理ツール推奨
- **Deno/Bunより、まずNode.js**。エコシステムと実績が違う

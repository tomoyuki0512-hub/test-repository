# ② 物理層とデータリンク層（L1/L2）

> **この章のゴール**：ケーブルとスイッチという「土台」を理解する。トラブルの過半数はこの層で起きるので、ここが分かると現場での解決速度が段違いに上がる。

← [① 基礎とOSI参照モデル](01-network-basics.md) ／ 次章 → [③ IPアドレスとサブネット](03-ip-subnet.md)

---

## 0. まず全体像（30秒）

- **L1（物理層）** = 信号を運ぶ道そのもの。ケーブル・電波・光。「0と1を電気/光の変化として表現する」
- **L2（データリンク層）** = 隣の機器まで確実に渡す仕組み。MACアドレスとスイッチが主役

```
L1 の問題 : 「そもそも繋がらない」「時々切れる」「速度が出ない」
L2 の問題 : 「繋がるのに通信できない」「突然ネットワーク全体が落ちた（ループ）」
```

現場のトラブルは、体感で **半分以上がこの2層**です。上位層を疑う前に、まずここを潰してください。

## 1. 物理層（L1）— 信号を運ぶ道

### 1-1. ツイストペアケーブル（LANケーブル）のカテゴリ

「LANケーブル」として売られている銅線ケーブルには**カテゴリ（CAT）**という等級があります。

| カテゴリ | 最大速度 | 最大周波数 | 最大距離 | 用途 |
| --- | --- | --- | --- | --- |
| CAT5 | 100Mbps | 100MHz | 100m | **もう使わない**（撤去対象） |
| CAT5e | 1Gbps | 100MHz | 100m | 既存設備に多い。1Gなら十分 |
| **CAT6** | 1Gbps（10Gは55mまで） | 250MHz | 100m | **現在の標準**。新規はここから |
| **CAT6A** | 10Gbps | 500MHz | 100m | **10G配線の本命**。オフィス新設の推奨 |
| CAT7 | 10Gbps | 600MHz | 100m | 端子規格がTERA。**業務用途では推奨しない**※ |
| CAT8 | 40Gbps | 2000MHz | **30m** | データセンタのラック内短距離のみ |

※ CAT7は「RJ45コネクタでの使用が規格上想定されていない」ため、市販の「CAT7ケーブル（RJ45付き）」は規格準拠ではありません。**迷ったらCAT6Aを選ぶ**のが実務の正解です。

> ⚠️ **距離100mの罠**：これは「機器〜機器」の総延長です。フロア配線（永久リンク）90m＋patch cord 両端5mずつ、で計100m。**壁内配線が長い建物では、机上の計算より早く上限に達します。**

#### シールドの有無

| 表記 | 意味 | 使う場面 |
| --- | --- | --- |
| **UTP** | 非シールド | 通常のオフィス。**基本はこれ** |
| **STP / FTP** | シールドあり | 工場・電源ケーブル近接・強いノイズ環境 |

STPは**両端で確実にアースを取らないと逆にノイズを拾います**。中途半端に使うくらいならUTPの方が安定します。

### 1-2. 光ファイバ

長距離・高速・ノイズ耐性が必要なら光を使います。

| 種類 | コア径 | 距離 | 用途 |
| --- | --- | --- | --- |
| **シングルモード（SMF）** | 9µm | 数km〜数十km | 建物間・キャンパス間・WAN |
| **マルチモード（MMF）** OM3/OM4/OM5 | 50µm | 〜300m/400m/550m | データセンタ内・フロア間 |

光ファイバの物理特性・コネクタ（SC/LC/MPO）・研磨（PC/UPC/APC）・損失計算については、本リポジトリに専用シリーズがあります。

> - [③ ケーブル・接続部材](../optical-fiber-cable-types.md)
> - [⑧ 光トランシーバとDC機器](../optical-fiber-transceiver-guide.md)（SFP/QSFP・PAM4）

### 1-3. 銅か光か、どちらを選ぶか

| 判断軸 | 銅（CAT6A） | 光（SMF/MMF） |
| --- | --- | --- |
| 距離 | 〜100m | 数百m〜数十km |
| コスト（機器込み） | 安い | トランシーバ（SFP）代がかかる |
| PoE（給電） | **できる** | できない |
| ノイズ耐性 | 弱い | **完全に無縁** |
| 施工の容易さ | 現場で成端しやすい | 融着には専用機材と技能が必要 |

**判断の目安**：同一フロア内は銅、フロア間・建物間は光。**Wi-Fi APや監視カメラへは給電が必要なので必ず銅**。

### 1-4. PoE（Power over Ethernet）— LANケーブルで給電する

Wi-Fi AP・IP電話・監視カメラは、**LANケーブル1本で電源も供給**できます。電源工事が不要になるため、設置自由度が劇的に上がります。

| 規格 | 通称 | 給電電力（給電側） | 主な用途 |
| --- | --- | --- | --- |
| 802.3af | PoE | 15.4W | IP電話、旧世代AP |
| 802.3at | PoE+ | 30W | Wi-Fi 6 AP、PTZカメラ |
| 802.3bt Type3 | PoE++ | 60W | Wi-Fi 6E/7 AP、デジタルサイネージ |
| 802.3bt Type4 | PoE++ | 100W | ノートPC、大型機器 |

> ⚠️ **PoE設計の落とし穴**：スイッチのカタログには「PoE対応24ポート」と書いてあっても、**総給電容量（PoEバジェット）が370W** といった上限があります。24ポート全部にPoE+（30W）を挿すと720W必要で、**全然足りません**。必ず「ポート数 × 必要電力 ≦ PoEバジェット」を検算してください。Wi-Fi 7 APは1台で60W超を要求する機種もあります。

### 1-5. 全二重・半二重とオートネゴシエーション

- **全二重（Full Duplex）**：送信と受信を同時にできる。現代は基本これ
- **半二重（Half Duplex）**：どちらか一方ずつ。衝突（コリジョン）が起きる

現代の機器は **オートネゴシエーション** で自動的に速度と二重方式を合わせますが、**片側だけ手動固定すると不一致（デュプレックスミスマッチ）が起きます**。

```
症状：疎通はする。pingも通る。でも「異常に遅い」「大きいファイルだけ失敗する」
原因：片側が全二重、片側が半二重 → 衝突が多発して再送だらけ
確認：スイッチで「late collision」カウンタが増えていないか
対処：両側ともオートネゴに戻す（片側だけ固定は最悪の設定）
```

**これは「遅い」系トラブルの古典的な原因**です。覚えておくと必ず役に立ちます。

## 2. データリンク層（L2）— 隣まで確実に渡す

### 2-1. MACアドレス

**MACアドレス**は、ネットワーク機器（NIC）に**製造時に焼き付けられた48ビットの識別子**です。

```
  aa:bb:cc : dd:ee:ff
  └─────┘   └─────┘
   OUI       個体番号
（ベンダー識別）（メーカー内の連番）

例: 00:1B:44:... = Cisco   /  3C:22:FB:... = Apple
```

- 前半24ビット（OUI）でメーカーが分かるため、**「この不明な機器は何？」の調査に使えます**
- 現代のスマホ・PCは、プライバシー保護のため**ランダムMACアドレス**を使うことがあります。MACアドレス認証を設計に使う場合は要注意（→ [⑦ 無線LAN](07-wireless-wan.md)）

### 2-2. スイッチはどう動いているのか

スイッチの動作は、たった3つのルールで説明できます。

```
【学習】フレームを受け取ったら、送信元MACと受信ポートを表に記録する
【転送】宛先MACが表にあれば、そのポートにだけ送る
【フラッディング】宛先MACが表になければ、受信ポート以外の全ポートに送る
```

この表を **MACアドレステーブル（CAMテーブル）** と呼びます。

```
確認コマンド（Cisco系）: show mac address-table

VLAN   MAC Address        Type      Ports
----   -----------        ----      -----
10     00:1b:44:11:22:33  DYNAMIC   Gi0/1
10     3c:22:fb:aa:bb:cc  DYNAMIC   Gi0/5
20     aa:bb:cc:dd:ee:ff  DYNAMIC   Gi0/24
```

> 💡 **「どのポートに何が繋がっているか分からない」**という現場でよくある問題は、このテーブルを見れば解決します。MACアドレスからOUIを調べればメーカーが分かり、機器を特定できます。

### 2-3. ハブとスイッチの違い（なぜハブは絶滅したか）

| | リピータハブ（L1） | スイッチ（L2） |
| --- | --- | --- |
| 転送先 | **全ポートにコピー** | 宛先のポートだけ |
| 帯域 | 全員で共有 | ポートごとに専有 |
| 通信方式 | 半二重（衝突あり） | 全二重 |
| 盗聴 | **他人の通信が丸見え** | 基本見えない |

ハブは「全員に聞こえるスピーカー」、スイッチは「個別の内線電話」です。**セキュリティ的にも性能的にも、ハブを新規導入する理由はゼロ**です。

## 3. VLAN — 1台のスイッチを複数に分ける

### 3-1. なぜVLANが必要か

理由は3つです。

| 理由 | 説明 |
| --- | --- |
| **ブロードキャストの抑制** | 同一セグメント内の全機器がブロードキャストを処理する。数百台になると無視できない負荷になる |
| **セキュリティの分離** | 「来客用Wi-Fi」から社内サーバーに到達させない。VLANが違えばL2では届かない |
| **物理配線からの独立** | 部署異動でも配線工事なしで、スイッチ設定だけで所属を変えられる |

### 3-2. アクセスポートとトランクポート

```
                    ┌──────────────┐
   PC(VLAN10) ──────┤ アクセスポート │
                    │              │
   PC(VLAN20) ──────┤ アクセスポート │  スイッチA
                    │              │
                    │ トランクポート │═══════╗  VLAN10と20の
                    └──────────────┘       ║  両方が流れる
                                            ║  （タグ付き）
                    ┌──────────────┐       ║
                    │ トランクポート │═══════╝
                    │              │  スイッチB
   PC(VLAN10) ──────┤ アクセスポート │
                    └──────────────┘
```

| 種類 | 役割 | タグ |
| --- | --- | --- |
| **アクセスポート** | 端末（PC・プリンタ）を繋ぐ。1つのVLANに所属 | タグなし |
| **トランクポート** | スイッチ同士・スイッチとルータを繋ぐ。複数VLANが通る | **802.1Q タグ付き** |

**802.1Q** は、フレームに4バイトのタグを挿入して「このフレームはVLAN 10のもの」と印を付ける規格です。これによって**1本のケーブルで複数のVLANを運べます**。

### 3-3. ネイティブVLANの注意点

トランクポートには「タグなしフレームをどのVLANとして扱うか」を決める**ネイティブVLAN**があります。既定値は VLAN 1 です。

> ⚠️ **セキュリティ上の定石**：
> - **ネイティブVLANは VLAN 1 以外に変える**（VLANホッピング攻撃の対策）
> - **VLAN 1 は業務に使わない**（管理用も別VLANにする）
> - トランクの両端でネイティブVLANを一致させる（不一致は通信不能や意図しない疎通を招く）

### 3-4. VLAN設計の実例（中規模オフィス）

| VLAN ID | 用途 | サブネット | 備考 |
| --- | --- | --- | --- |
| 10 | 有線クライアント | 10.10.10.0/24 | 社員PC |
| 20 | 無線クライアント（社員） | 10.10.20.0/24 | 802.1X認証 |
| 30 | **ゲストWi-Fi** | 10.10.30.0/24 | **インターネットのみ許可**。社内は全遮断 |
| 40 | サーバー | 10.10.40.0/24 | ファイルサーバー・業務システム |
| 50 | IP電話 | 10.10.50.0/24 | QoS優先。PoE給電 |
| 60 | 監視カメラ・IoT | 10.10.60.0/24 | **インターネット遮断**。管理端末からのみ到達 |
| 99 | **機器管理用** | 10.10.99.0/24 | スイッチ・APの管理IF。管理端末のみ到達 |

**設計の勘所**：VLAN番号とサブネットの第3オクテットを揃える（VLAN10 → 10.10.**10**.0/24）と、**運用時に頭を使わずに済みます**。これは強く推奨します。

## 4. ループとSTP — ネットワーク全体が落ちる恐怖

### 4-1. ブロードキャストストーム

L2にはループを検出する仕組みが**フレーム自体には存在しません**（L3のTTLに相当するものがない）。そのため、**スイッチ同士をループ状に繋ぐと、ブロードキャストフレームが永久に回り続けます。**

```
   スイッチA ══════ スイッチB
       ║               ║
       ╚═══ スイッチC ══╝

ブロードキャスト1発 → A→B→C→A→B→C→... と無限増殖
→ 数秒でCPU/帯域が飽和 → ネットワーク全体が停止
```

**症状**：全社のネットワークが突然、完全に止まる。スイッチのランプが全ポート激しく点滅。

**原因の大半**：「机の下で余ったLANケーブルの両端を、同じ島ハブに挿してしまった」という**人為的ミス**です。

### 4-2. STP（スパニングツリープロトコル）

STPは、**物理的にループしている経路のうち、一部を論理的にブロックして木構造にする**プロトコルです。

| 規格 | 通称 | 収束時間 | 現在の位置づけ |
| --- | --- | --- | --- |
| 802.1D | STP | 30〜50秒 | 遅すぎる。**もう使わない** |
| **802.1w** | **RSTP** | **数秒** | **現在の標準**。最低限これ |
| 802.1s | MSTP | 数秒 | VLANグループごとに別ツリー。大規模向け |
| — | PVST+ / Rapid PVST+ | 数秒 | Cisco独自。VLANごとにツリー |

### 4-3. 実務で必須の防御設定

STPを有効にするだけでは不十分です。以下は**必ず入れるべき設定**です。

| 機能 | 目的 | 設定するポート |
| --- | --- | --- |
| **BPDU Guard** | 端末ポートにスイッチが挿されたら即座に遮断 | 全アクセスポート |
| **PortFast / Edge Port** | 端末ポートは即座に通信可能にする（30秒待たない） | 全アクセスポート |
| **Root Guard** | 意図しない機器がルートブリッジになるのを防ぐ | 上位スイッチ側 |
| **Loop Detection / ループ検知** | ベンダー独自のループ検出。安価なスイッチにも搭載 | アクセスポート |
| **Storm Control** | ブロードキャストが閾値を超えたら破棄 | アクセスポート |

> 💡 **小規模オフィスの現実解**：STPを本格運用しないなら、せめて**ループ検知機能付きのスイッチ**を選んでください。数千円の差で、全社停止のリスクが大きく下がります。

### 4-4. ルートブリッジは必ず手動で決める

STPは「ブリッジID（優先度＋MACアドレス）が最小の機器」を自動でルートに選びます。放置すると、**たまたま古くてMACアドレスの小さい末端スイッチがルートになる**という事故が起きます。

```
必ずやること: コアスイッチの優先度を明示的に下げてルートに固定する
  例) spanning-tree vlan 1-100 root primary   （Cisco）
     → 副系にも root secondary を設定しておく
```

## 5. リンクアグリゲーション（LAG）— 束ねて太くする

複数の物理リンクを**1本の論理リンクとして束ねる**技術です。

```
   スイッチA ══╗
             ══╬══ 1Gbps × 4本 = 論理的に1本の 4Gbps
   スイッチB ══╝
```

| 呼び名 | 説明 |
| --- | --- |
| **LACP（802.3ad）** | 標準プロトコル。両端で自動的にネゴシエーション。**推奨** |
| Static / ON | 手動設定。ネゴなし。**設定ミスがループを生むので非推奨** |
| EtherChannel | Ciscoでの呼称 |
| ポートトランキング | 一部ベンダーでの呼称（802.1Qトランクとは別物なので注意） |

### 重要な注意：1セッションは1本しか使えない

**「4本束ねたから1つのファイル転送が4Gbpsになる」わけではありません。**

LAGは送信元/宛先のMAC・IP・ポート番号をハッシュして**使う物理リンクを決める**ため、**1つの通信（フロー）は必ず1本の物理リンクに固定されます**。

| 効果がある | 効果がない |
| --- | --- |
| 多数のユーザーが同時にアクセスする（合計帯域が増える） | 1台のサーバーへの単一の大容量転送 |
| 冗長性（1本切れても通信継続） | — |

単一フローで速度が必要なら、**素直に上位規格（10G/25G）にしてください**。

## 6. L2のセキュリティ機能

| 機能 | 防げる攻撃・事故 | 説明 |
| --- | --- | --- |
| **ポートセキュリティ** | 不正な端末の接続 | ポートごとに接続可能なMAC数/アドレスを制限 |
| **DHCPスヌーピング** | 不正DHCPサーバー | 信頼ポート以外からのDHCP応答を破棄 |
| **Dynamic ARP Inspection** | ARPスプーフィング（中間者攻撃） | DHCPスヌーピングの情報とARPを照合 |
| **IPソースガード** | IPアドレス詐称 | 送信元IPが払い出されたものと一致するか検証 |
| **802.1X** | 認証されていない端末 | 接続時にID/証明書で認証。**最も強力** |
| **プライベートVLAN** | 同一VLAN内の端末間通信 | ゲストWi-Fiで端末同士を隔離するのに有効 |

> ⚠️ **「不正DHCPサーバー」事故は本当によく起きます**。社員が家庭用ルータを持ち込んでLANポートに挿すと、そのルータがDHCPを配り始め、**その島の全員が通信不能**になります。DHCPスヌーピングを入れておけば防げます。

## 7. トラブルシューティング早見表（L1/L2）

| 症状 | 疑うべき原因 | 確認方法 |
| --- | --- | --- |
| リンクランプが点かない | ケーブル断線・ポート故障・速度不一致 | 別ケーブル／別ポートで切り分け |
| 頻繁に切れる（リンクフラップ） | ケーブル不良・コネクタ接触不良・PoE電力不足 | スイッチのログで up/down 回数を確認 |
| 極端に遅い | デュプレックスミスマッチ・ケーブル品質 | `show interface` でエラーカウンタ確認 |
| **全社が突然停止** | **ループ** | スイッチのCPU使用率・全ポートの点滅 |
| 特定の端末だけ通信不可 | VLAN設定ミス・ポートセキュリティ発動 | `show interface status` でerr-disable確認 |
| DHCPでIPが取れない | 不正DHCP・VLAN不一致・DHCPリレー未設定 | `ipconfig /all` で取得したIPの出所を確認 |
| 100mを超える配線で不安定 | 距離オーバー | 配線長の実測。光への変更を検討 |

### 見るべきエラーカウンタ

```
show interface GigabitEthernet0/1

  CRC errors        → ケーブル不良・ノイズ（L1）
  late collision    → デュプレックスミスマッチ（設定）
  input errors      → 物理的な問題全般
  runts / giants    → フレームサイズ異常（MTU不一致の可能性）
```

**カウンタが「増え続けているか」が重要**です。過去の累積値ではなく、`clear counters` して再測定してください。

## 8. よくある疑問（FAQ）

**Q. 「スイッチングハブ」はハブ？スイッチ？**
A. スイッチです。日本の商習慣で「ハブ」という語が残っているだけで、中身はL2スイッチ。リピータハブは市場からほぼ消えています。

**Q. インテリジェントスイッチと非管理型（アンマネージド）の違いは？**
A. VLAN・STP・SNMP監視・ポートミラーリングなどの設定・管理ができるかどうか。**VLANを使う予定があるなら、必ず管理型（マネージド）を選んでください**。後から「VLAN切りたい」となっても、アンマネージドでは不可能で、買い替えになります。

**Q. L2スイッチとL3スイッチの違いは？**
A. L3スイッチは**VLAN間のルーティングをハードウェアで高速に行える**スイッチです。中規模以上では「コアにL3スイッチを置いてVLAN間通信を捌く」のが定番構成になります（→ [⑨ 規模別構成](09-scale-patterns.md)）。

**Q. VLANはいくつまで作れる？**
A. 802.1Qでは 1〜4094。実用上、機器のスペック（スイッチごとのVLAN数上限）に依存します。数千VLANが必要な規模ではVXLAN（→ [⑧](08-cloud-network.md)）を使います。

## まとめ

- **L1のトラブルが最も多い**。ケーブル・距離・PoE電力を最初に疑う
- 新規配線は **CAT6A**、フロア間・建物間は**光**
- PoEは**総給電容量（バジェット）の検算**を忘れない
- スイッチは **学習・転送・フラッディング** の3ルールで動く
- **VLANは「ブロードキャスト抑制」「セキュリティ分離」「配線からの独立」**のために切る
- **ループは全社停止を招く**。RSTP＋BPDU Guard＋ループ検知は必須
- LAGは**合計帯域は増えるが、単一フローは速くならない**

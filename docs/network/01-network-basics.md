# ① ネットワークの基礎とOSI参照モデル

> **この章のゴール**：「なぜ機械同士が話せるのか」を層の考え方で説明できるようになる。そして、Webページが表示されるまでに何が起きているかを最初から最後まで追えるようになる。

← [総合インデックスに戻る](README.md) ／ 次章 → [② 物理層とデータリンク層](02-physical-datalink.md)

---

## 0. まず全体像（30秒）

ネットワークとは **「離れた機械が、共通のルールで情報を渡し合う仕組み」** です。

この「共通のルール」を **プロトコル（protocol）** と呼びます。日本語では「通信規約」。人間でいえば「日本語で話す」「敬語を使う」といった取り決めに相当します。

そして重要なのが、**プロトコルは1つではなく、役割ごとに何層にも積み重なっている**ということ。この積み重ねを **プロトコルスタック** と呼びます。

```
あなたがブラウザで https://example.com を開いたとき

  ① 「HTMLをください」という依頼を書く          → HTTP     (L7)
  ② それを暗号化する                           → TLS      (L6相当)
  ③ 分割して、順番と再送を保証する               → TCP      (L4)
  ④ 宛先の住所を書いて、経路を決める             → IP       (L3)
  ⑤ 隣の機器まで渡す宛名を書く                   → Ethernet (L2)
  ⑥ 電気信号／光／電波にして流す                 → 物理      (L1)
```

**この6ステップが、ネットワークのすべてです。** 以降の章は、この各段をひとつずつ深掘りしているだけ、と思ってください。

## 1. そもそもネットワークとは

### 1-1. 3つの要素しかない

どんなに複雑なネットワークも、分解すると3つの要素でできています。

| 要素 | 役割 | 具体例 |
| --- | --- | --- |
| **ノード（node）** | 通信する主体・中継する機器 | PC、サーバー、スマホ、ルータ、スイッチ |
| **リンク（link）** | ノード同士をつなぐ道 | LANケーブル、光ファイバ、Wi-Fiの電波 |
| **プロトコル** | 通信のルール | TCP/IP、HTTP、Ethernet |

「ネットワークが分からない」の正体は、たいてい **どのノードが、どのリンクで、どのプロトコルを話しているのか整理できていない** ことです。図を描くとほとんどの問題は解けます。

### 1-2. 規模による呼び名

| 呼び名 | 正式名称 | 範囲 | 誰が管理するか |
| --- | --- | --- | --- |
| **LAN** | Local Area Network | 建物・フロア内 | 自分たち（自社） |
| **WAN** | Wide Area Network | 拠点間・都市間 | 通信事業者（キャリア）から借りる |
| **MAN** | Metropolitan Area Network | 都市規模 | 通信事業者 |
| **PAN** | Personal Area Network | 数メートル（Bluetooth等） | 自分 |
| **インターネット** | — | 世界中 | 誰も管理していない（自律システムの集合） |

**LANとWANの決定的な違いは「所有しているかどうか」** です。LANは自分で機器を買って自由に設計できますが、WANは事業者から**借りる**ので、帯域も費用も契約に縛られます。この違いが構成設計に直結します（→ [⑦ WAN回線の選び方](07-wireless-wan.md)）。

### 1-3. 通信の3つの形

| 方式 | 意味 | 使われる場面 |
| --- | --- | --- |
| **ユニキャスト** | 1対1 | 通常のWebアクセス、ファイル転送 |
| **ブロードキャスト** | 1対「同一ネットワーク全員」 | ARP、DHCP要求。**IPv6には存在しない** |
| **マルチキャスト** | 1対「参加を表明したグループ」 | 社内動画配信、IPTV、OSPFの経路交換 |

> 💡 **なぜこれが重要か**：ブロードキャストは同じネットワーク内の**全機器**が受け取って処理します。機器が増えるほど無駄な負荷が増え、これが**ネットワークを分割（VLAN／サブネット化）する最大の理由**になります（→ [②](02-physical-datalink.md)・[③](03-ip-subnet.md)）。

## 2. OSI参照モデル — 7つの階層

### 2-1. なぜ層に分けるのか

理由はシンプルで、**「担当を分ければ、部品を差し替えられる」** からです。

郵便で考えてみましょう。手紙の**中身**（日本語で書くか英語で書くか）と、**運び方**（トラックか飛行機か）は independent です。中身を変えても運び方は変えなくていいし、逆もまた然り。

ネットワークも同じです。Wi-Fiから有線に切り替えても（L1/L2が変わっても）、ブラウザ（L7）は何も書き換える必要がありません。**これが階層化の威力です。**

### 2-2. 7階層の一覧

| 層 | 名前 | 役割（ひとこと） | 代表的なプロトコル | 代表的な機器 |
| --- | --- | --- | --- | --- |
| **L7** | アプリケーション層 | アプリが使う言葉 | HTTP、DNS、SMTP、SSH | — |
| **L6** | プレゼンテーション層 | 表現形式の変換・暗号化 | TLS/SSL、JPEG、文字コード | — |
| **L5** | セッション層 | 会話の開始と終了の管理 | NetBIOS、RPC | — |
| **L4** | トランスポート層 | 確実に届ける・アプリを識別 | **TCP、UDP** | ロードバランサ（L4） |
| **L3** | ネットワーク層 | 住所と経路 | **IP、ICMP** | **ルータ、L3スイッチ** |
| **L2** | データリンク層 | 隣の機器まで渡す | **Ethernet、ARP、PPP** | **スイッチ、ブリッジ** |
| **L1** | 物理層 | 電気信号・光・電波 | 1000BASE-T、Wi-Fi の物理仕様 | ハブ、リピータ、ケーブル |

**太字が実務で圧倒的によく出てくるもの**です。L5・L6 は現代ではほとんど意識されず、実質的に L7 に吸収されていると考えて構いません。

### 2-3. 覚え方

日本語の語呂合わせでは、下から **「アプセトネデブ」**（アプリケーション・プレゼンテーション・セッション・トランスポート・ネットワーク・データリンク・物理）を上から読む形が定番です。

ただし、**丸暗記より「L2 = 隣まで、L3 = 目的地まで、L4 = 確実に、L7 = 中身」の4つを腹落ちさせる**方が実務では役に立ちます。

## 3. TCP/IP 4階層モデル — 現実で使われているのはこっち

OSI参照モデルは**教科書上の理想モデル**です。実際のインターネットは **TCP/IP モデル（4階層）** で作られています。

| TCP/IP 4階層 | 対応する OSI | 具体例 |
| --- | --- | --- |
| **アプリケーション層** | L5〜L7 | HTTP、DNS、SMTP、SSH、TLS |
| **トランスポート層** | L4 | TCP、UDP、QUIC |
| **インターネット層** | L3 | IP、ICMP、ARP※ |
| **ネットワークインターフェース層** | L1〜L2 | Ethernet、Wi-Fi、PPPoE |

※ ARP は厳密には L2 と L3 の境界に位置します。

### なぜ2つのモデルがあるのか

- **OSI**：ISO（国際標準化機構）が「あるべき姿」として策定。**議論と切り分けの共通言語**として今も使われる
- **TCP/IP**：実際に動くものとして先に普及。**現実の実装**

実務では **「レイヤ3の問題ですね」のようにOSIの番号で会話し、実装はTCP/IPで動いている**、という二重構造になっています。両方知っておく必要があるのはそのためです。

## 4. カプセル化 — データが包まれていく仕組み

### 4-1. 送信側：下の層に降りるたびに包む

データは層を下るたびに、その層の**ヘッダ（宛名書き）**を付けられます。これを **カプセル化（encapsulation）** といいます。

```
【アプリケーション層】
   GET /index.html HTTP/1.1 ...            ← データ本体

【トランスポート層】TCPヘッダを前に付ける
   [TCPヘッダ][ HTTPデータ ]                 ← セグメント
    └ 送信元ポート / 宛先ポート80 / シーケンス番号

【インターネット層】IPヘッダを前に付ける
   [IPヘッダ][TCPヘッダ][ HTTPデータ ]        ← パケット
    └ 送信元IP 192.168.1.10 / 宛先IP 93.184.216.34

【ネットワークインターフェース層】Ethernetヘッダとトレーラを付ける
   [Ethヘッダ][IPヘッダ][TCPヘッダ][ データ ][FCS]  ← フレーム
    └ 送信元MAC / 宛先MAC（＝次のルータのMAC）
```

受信側は逆順に「開封（非カプセル化）」していきます。**入れ子の箱**をイメージしてください。

### 4-2. 呼び名が層ごとに違う

| 層 | データの呼び名 |
| --- | --- |
| L7 | データ／メッセージ |
| L4 | **セグメント**（TCP）／**データグラム**（UDP） |
| L3 | **パケット** |
| L2 | **フレーム** |
| L1 | ビット |

会話の中で「パケットが落ちてる」と言えばL3の話、「フレームエラーが出てる」と言えばL2の話、と**層が特定できます**。これがトラブル切り分けの入口になります。

### 4-3. MTU — 一度に運べる大きさ

1つのフレームで運べるデータの上限を **MTU（Maximum Transmission Unit）** といいます。Ethernet では **1500バイト** が標準です。

| 環境 | MTU | 備考 |
| --- | --- | --- |
| 標準 Ethernet | 1500 | 最も一般的 |
| PPPoE（フレッツ等） | 1454 / 1492 | ヘッダ分減る。**設定ミスの温床** |
| IPsec VPN | 1400前後 | 暗号化ヘッダの分さらに減る |
| ジャンボフレーム | 9000 | データセンタ内・iSCSI等で使用 |

> ⚠️ **実務で頻出のトラブル**：「pingは通るのに、Webページの一部だけ表示されない／VPN越しにファイル転送が止まる」。これはほぼ **MTU不一致（＋PMTUD失敗）** です。パケットが大きすぎて分割が必要なのに、ICMPがブロックされていて通知が届かない状態。詳しくは [⑪ トラブルシューティング](11-operations.md) で扱います。

## 5. 通信の一部始終 — `https://example.com` を開くと何が起きるか

ここまでの知識を全部使って、実際の流れを追ってみます。**この節が本章の山場です。**

### 前提

- あなたのPC：`192.168.1.10`／デフォルトゲートウェイ `192.168.1.1`
- example.com のサーバー：`93.184.216.34`

### ステップ 1：名前をIPアドレスに変換する（DNS・L7＋L4）

```
PC:  「example.com のIPアドレスは？」
      → DNSキャッシュサーバー（例: 192.168.1.1 や 8.8.8.8）へUDP 53番ポートで問い合わせ
DNS: 「93.184.216.34 です」
```

内部では、ルートDNS → `.com` の権威サーバー → example.com の権威サーバー、と階層をたどっています（詳細は [DNS・ドメイン完全ガイド](../dns-guide.md)）。

### ステップ 2：宛先が「同じネットワークか」を判定する（L3）

PCは自分のIPとサブネットマスクから、宛先が**同じセグメントにいるか**を計算します。

```
自分     : 192.168.1.10 / 255.255.255.0  → 自分のネットワークは 192.168.1.0〜255
宛先     : 93.184.216.34                → 範囲外！
結論     : 「外だ。デフォルトゲートウェイ（192.168.1.1）に投げよう」
```

**この判定が L3 の中心的な仕事**です（→ [③ IPアドレスとサブネット](03-ip-subnet.md)）。

### ステップ 3：ゲートウェイのMACアドレスを調べる（ARP・L2）

IPは分かっても、実際にケーブルに流すには**隣の機器のMACアドレス**が必要です。

```
PC:      「192.168.1.1 の人、MACアドレス教えて！」（ブロードキャスト）
ルータ:  「私です。aa:bb:cc:dd:ee:ff です」（ユニキャストで返答）
```

> 💡 ここが最重要ポイント：**宛先IPは example.com のまま、宛先MACはルータのもの**になります。IPは「最終目的地」、MACは「次の1ホップ」。この二重構造が理解できれば L2/L3 の混乱は解消します。

### ステップ 4：TCPコネクションを確立する（L4）

```
PC   → サーバー : SYN            「話しかけていい？」
PC   ← サーバー : SYN + ACK      「いいよ、そっちも聞こえてる？」
PC   → サーバー : ACK            「聞こえてる。始めよう」
```

これが **3ウェイハンドシェイク**です（→ [⑤](05-transport-application.md)）。

### ステップ 5：TLSで暗号化の準備をする

証明書の提示・検証と鍵交換を行い、以降の通信を暗号化します。HTTPSの「S」の正体です。

### ステップ 6：HTTPでリクエストを送る（L7）

```
GET / HTTP/1.1
Host: example.com
```

サーバーがHTMLを返し、ブラウザが描画します。画像やCSSがあれば、その分だけステップ1〜6が繰り返されます。

### ステップ 7：途中の経路では何が起きているか

パケットは複数のルータを経由します。**ルータを通るたびに書き換わるもの／変わらないもの**があります。

| 情報 | ルータ通過時 | 理由 |
| --- | --- | --- |
| 宛先IPアドレス | **変わらない**※ | 最終目的地だから |
| 送信元IPアドレス | **変わらない**※ | 返信先だから |
| 宛先MACアドレス | **毎回変わる** | 「次の1ホップ」の宛名だから |
| 送信元MACアドレス | **毎回変わる** | 転送したルータ自身になる |
| TTL | **1ずつ減る** | ループ防止。0になると破棄される |

※ NAT（→ [③](03-ip-subnet.md)）を通る場合は送信元IPが書き換わります。家庭やオフィスからインターネットに出るときは必ずこれが起きています。

> この表を理解できていれば、**あなたはもうネットワークの基礎を押さえています。** `traceroute`（Windowsは `tracert`）を実行すると、TTLの仕組みを利用して経路を可視化できます。

## 6. よく使う基本コマンド

トラブル時に真っ先に叩くコマンドです。**上の層から順ではなく、下の層から順に**確認するのがコツ。

| 目的 | Linux / macOS | Windows |
| --- | --- | --- |
| 自分のIPを見る | `ip addr` | `ipconfig /all` |
| 疎通確認（L3） | `ping 8.8.8.8` | `ping 8.8.8.8` |
| 経路を追う（L3） | `traceroute example.com` | `tracert example.com` |
| 名前解決の確認（L7） | `dig example.com` | `nslookup example.com` |
| 通信中の接続を見る（L4） | `ss -tunap` | `netstat -ano` |
| ARPテーブル（L2） | `ip neigh` | `arp -a` |
| 経路表（L3） | `ip route` | `route print` |
| ポート疎通（L4） | `nc -zv host 443` | `Test-NetConnection host -Port 443` |

### 切り分けの黄金パターン

```
1. ケーブル・リンクランプは点いているか          → L1
2. 同じセグメント内の機器にpingは通るか            → L2 + L3
3. デフォルトゲートウェイにpingは通るか            → L3
4. 8.8.8.8（IP直打ち）にpingは通るか              → L3（インターネット到達性）
5. 名前解決はできるか（dig）                      → L7（DNS）
6. 目的のポートに繋がるか（nc / Test-NetConnection）→ L4（FW・フィルタ）
```

**4は通るのに5が失敗 → DNSの問題。5は通るのに6が失敗 → ファイアウォールの問題。** このように、どこで止まったかで原因の層が特定できます。

## 7. よくある疑問（FAQ）

**Q. IPアドレスとMACアドレス、両方必要なのはなぜ？**
A. 役割が違うからです。MACアドレスは**製造時に焼き付けられた固定の識別子**で、どこにいるかの情報を含みません。IPアドレスは**今どのネットワークにいるか**を表す住所です。世界中の機器をMACだけで探すのは、名前だけで人を探すのと同じで不可能。一方IPは「日本の東京都の…」と絞り込めるので、経路を計算できます。

**Q. スイッチとルータの違いは？**
A. **スイッチはL2（同じネットワーク内での転送）、ルータはL3（異なるネットワーク間の転送）**。家庭用の「ルータ」は、実際にはルータ＋スイッチ＋無線AP＋NAT＋DHCPサーバーが1台に入った複合機です。

**Q. なぜ「ネットワークが遅い」の原因究明は難しいのか？**
A. 遅さの原因が全層に散らばっているからです。ケーブル不良（L1）、スイッチのループ（L2）、経路の迂回（L3）、TCP再送（L4）、DNSの遅延（L7）、そしてサーバー自体の遅さ（ネットワーク外）。だからこそ**層ごとに切る**手順が必要になります。

**Q. IPv6は覚えるべき？**
A. はい。モバイル網とクラウドではすでに標準です。ただしIPv4が消えるわけではなく、**当面は両方が並走（デュアルスタック）** します（→ [③](03-ip-subnet.md)）。

---

## まとめ

- ネットワークは **ノード・リンク・プロトコル** の3要素でできている
- **層に分ける**ことで、部品の差し替えと問題の切り分けが可能になる
- 実装は **TCP/IP 4階層**、会話は **OSI 7階層の番号**で行われる
- データは下の層に降りるたびに**カプセル化**され、L4=セグメント、L3=パケット、L2=フレームと呼び名が変わる
- **IPは最終目的地、MACは次の1ホップ** —— この違いが全ての基礎
- 切り分けは必ず **下の層から**
